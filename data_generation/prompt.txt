You are a "God View" Synthetic Data Generator for a Context-Aware Assistant Protocol.
Your goal is to generate a **High-Density "Gold Standard" Dataset** for training an Assistant-to-Assistant communication system.

### 1. THE CORE LOGIC (READ CAREFULLY)
* **The "Gap":** Assistant A records **ONLY** User A. Assistant B records **ONLY** User B. They cannot hear the other person.
* **The Problem:** When User B says "Let's meet at *Joe's Pizza*," Assistant A hears silence, then User A saying "Okay." Assistant A misses the location entity.
* **The Goal:** Generate the conversation AND the specific **Protocol Queries** needed to fill these gaps.

### 2. STRICT CONSTRAINTS
1.  **Length:** ~2,000 words (Approx 15 mins of dialogue).
2.  **High Density:** Include 15+ local context resolutions (here, there, him) and 8+ inter-agent queries.
3.  **"Usefulness" Filter (CRITICAL):**
    * **DO NOT** generate a query for small talk. (e.g., If User B tells a joke and A laughs, do NOT ask "What was the joke?").
    * **ONLY** generate a query if the missing info is **Actionable** (Time, Location, Contact Name) or **Sensitive** (Privacy decision).

### 3. GENERATION STEPS

**Step 1: The World State**
Define a complex scenario (e.g., Organizing a protest, Planning a secret surprise, Managing a crisis).

**Step 2: The Metadata (Sensors)**
Generate valid JSON metadata for BOTH users (GPS, Wifi, Calendar) that explains the "local" context (e.g., Why "here" = "Central Park").

**Step 3: The Conversation**
Write the dialogue.
* **Force Ambiguity:** Users should rely on context. ("I'm *here*", "Did you ask *him*?").
* **Force Gaps:** User B should propose plans/names. User A should agree without repeating the name.

**Step 4: The Answer Keys (Protocol Outputs)**
* **Resolutions:** Map "here" -> "GPS Coordinates".
* **Queries:** Generate **Structured Protocol Payloads** for the missing info.
